▓▓▓ 1. 什么是 EGREGOR ▓▓▓

Egregor 是一个桌面应用程序，它以协作模式运行多个 AI 模型（来自 Anthropic、Google、OpenAI、DeepSeek、Qwen、Meta、Mistral、xAI 等）。它们不只是并行回应 — 它们辩论、相互批评、综合一个共同的判决，最重要的是：它们看到单个 AI 会忽略的内容。

单独使用时，任何 AI 都可能犯错、产生幻觉、遗漏细节。但当 4-7 个 AI 在主持人的指导下共同工作时，会出现"智慧共振" — 每个模型都能弥补其他模型的弱点。这对于复杂任务特别有价值：智能合约审计、战略决策、关键代码审查、写作书籍、寻找非常规想法。

Egregor 在你的计算机上本地运行（Windows、macOS、Linux），并通过统一的 API — OpenRouter.ai 连接到模型。


▓▓▓ 2. 哲学与架构 ▓▓▓

主要思想不是"比较 5 个 AI 的意见"，而是从集体讨论中获得一个全新的答案。

架构层：
• AI 模型 — 系统的大脑
• 角色 — 每个 AI 都有其功能（开发者、安全审计员、创意者、事实核查员...）
• 主持人 — 综合其他人答案的主要 AI
• 上下文扩展 — Soul Document、Big Text、Project Dossier、Big Project Map
• 保护机制 — 反群体思维、红队、信心地图

Egregor 安装免费。你只需通过 OpenRouter 支付实际使用的令牌 — 通常每次请求几美分。许多模型完全免费。


▓▓▓ 3. 首次启动 ▓▓▓

第一步. 获取 OpenRouter API 密钥
→ 打开 https://openrouter.ai（标题栏中的 🔗 OpenRouter 按钮）
→ 注册（Gmail 或电子邮件）
→ "Keys" 部分 → "Create Key" → 复制

第二步. 将密钥粘贴到 Egregor
→ 右上角的 🔴 无密钥按钮
→ 粘贴密钥 → 保存
→ 应变为 🟢 主要

第三步. 填写"我的背景"（5 分钟 — 物超所值）
→ 标题栏中的 📝 我的背景按钮
→ 描述你是谁、做什么、有哪些项目
→ 保存
→ 现在所有 AI 都知道背景并调整答案

第四步. 选择预设或组建你的会议
→ 在标题栏中："通用 🌐"、"代码开发 💻"、"创意 🎨"、"策略 🚀"
→ 或"更多预设 ▾" — 25 个预制套件
→ 你可以自己组建：左侧面板中的"+"按钮

第五步. 提出你的第一个问题
→ 只需在下方字段中输入
→ 用 📎 按钮或拖放附加文件

▓▓▓ 4. API 密钥 ▓▓▓

══ 4.1 什么是 OPENROUTER ══

OpenRouter.ai 是一个统一的 API 网关，连接所有领先提供商的 300+ AI 模型。一个密钥 — 访问一切。价格与原始提供商匹配（或通过 OpenRouter 上的免费提供商更便宜）。

══ 4.2 获取密钥 ══

1. 打开 openrouter.ai（或 Egregor 中的 🔗 OpenRouter 按钮）
2. 注册
3. 充值余额（最低 $5 — 持续很长时间，或仅使用 🆓 模型）
4. "Keys" 部分 → "Create Key"
5. 复制密钥（以 sk-or-v1-... 开头）
6. 粘贴到 Egregor：🔴 无密钥按钮 → 保存

══ 4.3 免费 🆓 模型 ══

OpenRouter 免费提供几个模型（有速率限制但足以应付大多数任务）。在 Egregor 目录中标记为 🆓：

• DeepSeek R1 🆓 — 深度推理
• DeepSeek V3 🆓 — 通用，质量良好
• Qwen3 Coder 480B 🆓 — 顶级编码器
• Qwen 3 235B 🆓 — 通用
• Llama 4 Maverick 🆓 — 来自 Meta
• Gemma 3 🆓 — 来自 Google
• Nemotron 3 Super 🆓 — 来自 Nvidia

══ 4.4 技巧：两个密钥节省 ══

最有用的技巧之一：
• "主要"密钥 — 你的主账户带余额
• "免费"密钥 — 仅用于 🆓 模型的单独账户

这样免费模型通过第二个账户的限制工作，不与你的主要账户竞争。将每天免费请求数翻倍。

══ 4.5 在密钥之间切换 ══

标题栏中的 🟢 按钮打开密钥管理器。单击密钥使其活动 — 所有后续请求都通过它。当一个的限制耗尽时方便。

══ 5.3 免费模型 ══

OpenRouter 上的免费模型有速率限制（每个密钥约 20 个请求/分钟，约 200 个/天）。足以应付大多数任务。

策略：
1. 使用 🆓 模型作为第一层
2. 如果结果不满意 — 切换到付费
3. 使用两个密钥（参见 4.4）使每日限制翻倍

══ 5.4 自定义 OPENROUTER 模型 ══

Egregor 目录会随着新版本更新。但如果 OpenRouter 添加了目录中尚未有的新模型 — 你可以手动使用它：
1. 在 Egregor 目录（或管道编辑器）中选择"＋ 输入任何 OpenRouter 模型 ID..."
2. 以提供商/模型名称形式输入 ID
3. Egregor 将保存并使用它


▓▓▓ 6. 活动 AI ▓▓▓

══ 6.1 添加和删除 ══

左侧 — 活动 AI 面板。通过"+"添加，通过 🗑 删除。"活动"切换 — 临时禁用。

一个会议可以有 1 到 10 个 AI。最佳 3-5 个，以保证质量和速度。

══ 6.2 角色 ══

每个 AI 都有一个角色：
👑 主持人 — 综合他人的答案
💻 开发者 — 深度代码分析
🛡️ 安全 — 漏洞搜索
🎨 创意 — 非常规想法
📋 审计员 — 批判性分析
🔍 事实核查员 — 信息准确性
💼 业务分析师 — 市场视角
🎭 魔鬼代言人 — 攻击共识
👁️ 观察者 — 中立位置

══ 6.3 主持人 ══

其中一个 AI 始终标有 👑。他接收所有其他人的答案，分析它们并给出最终综合。

建议：将最强模型设置为主持人 — 重要任务的 Claude Opus 4.7 或 Sonnet 4.6。

▓▓▓ 7. 四种主要模式 ▓▓▓

══ 7.1 🤖 单一模式 ══

当会议中只有一个 AI 时自动激活。像普通 ChatGPT 风格的聊天一样工作。

══ 7.2 📊 集体分析 ══

一轮：所有 AI 并行回答，主持人做最终综合。比实时会议更便宜更快。

══ 7.3 🏛️ 实时会议 ══

Egregor 的主要模式。多轮讨论：
第 1 轮：每个 AI 用其角色回答你的问题。
第 2 轮：每个 AI 读取其他人说的话，批评，补充。
第 3 轮（可选）：寻找共识。
最终：主持人综合一切。

══ 7.4 💻 代码审查管道 ══

代码审计专用模式。5 个 AI 严格按顺序工作：
1. ✍️ 推理 — 深度分析
2. 🛡️ 安全 — 漏洞搜索
3. 🔧 替代 — 重写问题区域
4. ⚖️ 比较 — 比较选项
5. 👑 最终裁决 — 最终建议

══ 7.5 📖 大文本 ══

上下文扩展。对于 >40,000 字符的文档：一个 AI 完整读取并创建摘要，其他 AI 使用它工作。

▓▓▓ 8. 质量与经济开关 ▓▓▓

══ 8.1 顺序 ══

默认情况下所有 AI 并行回答。如果你的计算机较弱 — 启用"顺序"。AI 将严格地一个接一个地回答。

══ 8.2 💰 经济模式 ══

固定 2 轮，回答 ~150 字，裁决 ~500 字。节省 ~75% 令牌。与反群体思维不兼容。

══ 8.3 🛡️ 反群体思维 ══

防止群体思维的主要保护。激活两个机制：

🎭 盲眼第一轮 — 所有 AI 不看角色回答。
⚔️ 轮换魔鬼代言人 — 在每轮中一位参与者暂时成为批评者。

⚠️ 大约多消耗 +30% 令牌。与经济模式不兼容。

══ 8.4 🛡️ 红队 ══

反群体思维的子选项。对已建立共识的最终攻击轮次。⚠️ 增加约 15% 令牌。

══ 8.5 📊 信心地图 ══

每次最终裁决后，主持人在 1-5 等级上评估信心：

🟢 5/5 — 完全同意
🟢 4/5 — 强烈同意
🟡 3/5 — 中等同意
🟠 2/5 — 弱同意
🔴 1/5 — 没有同意

══ 8.6 🔗 OPENROUTER ══

用于快速导航到 openrouter.ai/models 的按钮。

▓▓▓ 9. 📝 我的背景 (SOUL DOCUMENT) ▓▓▓

Soul Document 是你给所有 AI 的名片。填写一次 — 任何项目中的任何 AI 都知道你是谁。

标题栏中的 📝 我的背景按钮。

有用指定：
• 姓名和活动领域
• 专业知识水平
• 活动项目
• 喜欢的技术、编程语言
• 沟通风格
• 个人特征

长度 — 200 到 2000 字。Soul Document 自动附加到任何 AI 的每个系统提示。

▓▓▓ 10. 文件类型 ▓▓▓

══ 10.1 文本和代码 ══

支持的主要格式：.md, .txt, .json, .yaml, .js, .ts, .py, .sol, .rs, .go, .c, .cpp, .java, .kt, .swift, .php, .rb, .lua, .sh, .sql 等。

每个文件最大 500 KB，读入上下文最多 12,000 字符。

══ 10.2 PDF 和 OFFICE ══

PDF 完全支持。Word (.docx) 和 PowerPoint (.pptx) — 部分支持。

══ 10.3 图像 ══

支持 .png, .jpg, .gif, .webp。具有视觉支持的 AI 分析图像。

══ 10.4 书籍 ══

EPUB、FB2、RTF — 已读取。对于大书籍，建议使用 📖 大文本模式。

══ 10.5 归档 ══

通过 node-7z + 7zip-bin：ZIP、RAR、7Z、TAR、GZ、BZ2、XZ。嵌套归档最多 3 级。

══ 10.6 拖放和 📎 ══

两种方式：📎 按钮或拖放。⚠️ 对于 Electron 32+：在 Windows 上拖放归档时使用 📎。限制：同时附加最多 15 个文件。

▓▓▓ 13. 项目 ▓▓▓

项目是保存的工作上下文：会议组成、消息历史、档案、项目地图、缓存、文件。

项目自动保存到 localStorage。"保存到文件"将所有内容导出为 JSON 用于备份。

单击项目 → 🗑 删除。删除不可逆。

⚠️ localStorage 有限（~5-10 MB）。定期导出和清理。

▓▓▓ 14. 📊 令牌和成本统计 ▓▓▓

📊 统计按钮打开详细会计：每个模型的令牌、美元成本、按天/周/月分组。CSV 导出。价格从 openrouter.ai 自动更新。


▓▓▓ 15. 📖 大文本 ▓▓▓

对于 >40,000 字符的文档。激活时：
1. 一个 AI（默认 Gemini 2.0 Flash）完整读取
2. 创建 7 部分结构化摘要
3. 这些 ~5,000 令牌作为其他 AI 的上下文
4. 你提问 — 所有 AI 看到摘要

附加 >40,000 字符的文件时 Egregor 自己建议激活模式。


▓▓▓ 16. 📚 上下文压缩引擎 ▓▓▓

Project Dossier — 项目整个对话的紧凑摘要。由一个 AI（守护者）创建并替换完整历史在上下文中。

何时激活：
• 长项目（30+ 条消息）
• 当答案变得昂贵时

默认情况下档案由 Gemini 2.0 Flash 维护。可在 📚 设置 → ⚙️ 中更改。

档案结构（5 部分）：主要话题、决定、未解决问题、关键事实、动态。

自动更新每 6 条消息或超过 50k 令牌时。

实际节省：长项目中节省 10-20 倍令牌。


▓▓▓ 17. 🧠 语义缓存 ▓▓▓

如果你过去问过类似的问题 — Egregor 将返回相同的答案，无需 API 调用。

每个问题通过 embeddings 模型（默认 openai/text-embedding-3-small）转换为向量。

匹配阈值：
• >95% — 静默从缓存返回 🔁
• 85-94% — 询问"使用先前答案？"
• <85% — 正常 API 请求

缓存禁用：带附件的请求、时间相关查询（带"今天"、"新闻"、"汇率"等词）。

清除缓存：⚙️ → 清除缓存。

▓▓▓ 18. 💻 代码审查管道 ▓▓▓

代码审查管道 — 第四种工作模式。5 个 AI 严格按顺序工作：

步骤 1. ✍️ 推理 — 深度分析
代码做什么？架构。假设。逻辑问题。

步骤 2. 🛡️ 安全 — 漏洞搜索
智能合约：reentrancy、integer overflow、access control。Web：SQL injection、XSS、CSRF。

步骤 3. 🔧 替代 — 替代实现
重写问题区域。

步骤 4. ⚖️ 比较 — 比较
替代方案在哪里更好/更糟。权衡。公正裁决。

步骤 5. 👑 最终裁决 — 最终建议
🔴 关键 / 🟡 推荐 / 🟢 可选 / ✅ 保持原样 / 💡 最终代码

智能合约审计的理想组成：
步骤 1 → DeepSeek R1 🆓（深度思考）
步骤 2 → Claude Sonnet 4.6（顶级安全）
步骤 3 → Qwen3 Coder 480B 🆓（顶级编码器）
步骤 4 → GPT-4.1（客观分析师）
步骤 5 → Claude Opus 4.7（最终裁判）

5 个模型中有 3 个 — 免费。审计成本 ~$0.30-0.50，而 CertiK 为 $5,000-50,000。


▓▓▓ 19. ⚙️ 管道编辑器 ▓▓▓

💻 代码审查旁边的 ⚙️ 按钮打开设置。两种模式：

🤖 自动 — Egregor 自己根据角色从活动会议中选择 AI
✋ 手动 — 你为每个步骤分配特定模型

在手动模式下，每个步骤都有一个下拉菜单，包含三组：
🟢 会议中活动
🤖 Anthropic / 🔵 Google / 🟢 OpenAI / ... — 完整目录

每个步骤左侧的复选框 — 可以禁用。⚠️ 最终步骤 👑 是必需的。

管道设置保存到 localStorage。


▓▓▓ 20. 📦 大项目模式 — 代码库分析 ▓▓▓

激活时：
✅ 所有文件完整读取（无截断）
✅ 导入解析 — 依赖图
✅ 守护者编写"项目地图"
✅ 按函数分块、嵌入
✅ 每次请求的 RAG 搜索
✅ 与代码审查管道集成

阶段 1：索引和项目地图

1. 解压 — 归档到 %TEMP%/egregor_big_projects/{projectId}/src/
2. 读取 — 所有代码文件完整（每个文件 2 MB 限制，每个项目 50 MB 和 500 个文件）
3. 导入解析 — Solidity、JS/TS、Python、Rust、Go
4. 依赖图 — 直接和反向
5. 项目地图 — 守护者（Gemini 2.0 Flash）编写 7 部分摘要

阶段 2：分块和嵌入 (RAG)

1. 分块 — 每个文件按函数
2. 嵌入 — 通过 OpenRouter 生成（每块 ~$0.0001）
3. RAG 搜索 — 每个请求的前 8 个相关块

阶段 3：与代码审查集成

每个管道步骤根据其专业化进行自己的 RAG 搜索：
步骤 1 → 入口点、公共函数
步骤 2 → 外部调用、msg.sender、delegatecall
步骤 3 → 关键路径
步骤 4 → 使用结果
步骤 5 → 所有函数的摘要

支持的语言：
导入解析：Solidity、JS、TS、Python、Rust、Go
分块：相同 + 通过正则表达式扩展
读取（无分块）：Java、Kotlin、Swift、C/C++、C#、Dart、PHP、Ruby、Lua、Shell、SQL、Vue、Svelte 等

限制：
• 项目文件 — 500
• 单个文件大小 — 2 MB
• 总项目大小 — 50 MB
• 归档嵌套 — 3 级
• 忽略：node_modules、.git、dist、build、target、.venv

会话之间的存储：
在 %TEMP%/egregor_big_projects/{projectId}/：
• src/ — 解压的代码文件
• index.json — 元数据
• embeddings.json — 向量

清理：大项目面板中的 🗑 按钮。

▓▓▓ 23. 常见问题和错误解决 ▓▓▓

"Insufficient credits"
→ OpenRouter 余额用完。充值或使用 🆓 模型。

"Rate limit exceeded"
→ 等一会儿或换密钥。

"Model not found"
→ 模型 ID 拼写错误。检查 openrouter.ai/models。

Egregor 启动慢
→ 首次启动 5-7 秒 — 正常。

输入字段冻结
→ 大项目索引中。等待 ~30 秒。

按钮不可见
→ 窗口太窄。展开。

免费模型不工作
→ 速率限制。使用两个密钥。

聊天变慢/昂贵
→ 上下文增长。激活 📚 压缩。

大项目不索引
→ 检查归档是否包含代码文件（支持的扩展名）。

PDF 不解析
→ 安装 pdf-parse。Windows 上拖放可能有问题 — 使用 📎。

Windows 上拖放归档
→ Electron 32+ 已知错误。使用 📎 按钮代替拖动。

项目消失
→ 数据在 localStorage 中。定期使用"保存到文件"备份。
